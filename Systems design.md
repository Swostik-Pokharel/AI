# Design Principles & Patterns - Basics

## Core Principles

### SOLID Principles

- **Single Responsibility** - One class, one job
- **Open/Closed** - Open for extension, closed for modification
- **Liskov Substitution** - Subtypes can replace base types
- **Interface Segregation** - Many small interfaces over one large
- **Dependency Inversion** - Depend on abstractions, not concrete classes

### Other Key Principles

- **DRY** - Don't Repeat Yourself
- **KISS** - Keep It Simple, Stupid
- **YAGNI** - You Aren't Gonna Need It

---

## Essential Design Patterns

### Creational

- **Singleton** - One instance of a class
- **Factory** - Create objects without specifying exact class
- **Builder** - Build complex objects step by step

### Structural

- **Adapter** - Make incompatible interfaces work together
- **Decorator** - Add behavior to objects dynamically
- **Facade** - Simplified interface to complex system

### Behavioral

- **Strategy** - Swap algorithms at runtime
- **Observer** - Notify multiple objects of changes
- **Template Method** - Define algorithm skeleton, let subclasses fill in steps
